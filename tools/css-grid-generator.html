A CSS Grid generator for track design, not only column counting

Real CSS Grid work often requires mixed track sizes. A content area may need twice the space of a sidebar; a navigation rail may need a fixed width; a card collection may need tracks that grow but never become narrower than a usable minimum. This tool accepts actual track syntax so the preview represents those decisions.

Enter values such as 2fr 1fr, 240px minmax(0, 1fr), or repeat(3, minmax(12rem, 1fr)). Separate row and column gaps make asymmetric systems possible, while the viewport buttons expose where an explicit desktop grid needs a mobile fallback.

Track-sizing examples

Content and sidebar

minmax(0, 2fr) minmax(16rem, 1fr) protects the sidebar while allowing the primary area to absorb remaining space.

Equal cards

repeat(3, minmax(0, 1fr)) creates equal tracks and prevents overflowing descendants from widening them.

Intrinsic navigation

max-content minmax(0, 1fr) gives navigation the width it needs and leaves the rest for content.

How to reason about the generated CSS

  1. Explicit tracks describe the intended wide-screen composition.
  2. Column and row gaps are independent because editorial layouts often need different horizontal and vertical rhythm.
  3. The mobile fallback deliberately simplifies to one track; complex desktop areas should not be squeezed blindly.
  4. Items are left in source order so the fallback remains understandable.

CSS Grid versus Flexbox

Use Grid when rows and columns form a meaningful two-dimensional relationship. Use Flexbox when the main problem is distributing items along one axis, such as a toolbar or button group. They are complementary: a grid card can contain a flex row, and a flex-based shell can contain a grid gallery.

Accessibility and failure testing

CSS layout does not change semantics. Use landmarks, headings, lists, articles, and navigation according to the content. Test a very long unbroken string, translated labels, zoom, missing cards, and narrow containers. Add min-width: 0 to grid children that contain code, tables, or long text when overflow appears.

Common mistakes

  • Using 1fr without understanding its automatic minimum.
  • Defining rows with fixed heights when content can wrap.
  • Leaving explicit multi-column tracks active on narrow screens.
  • Using grid areas to visually reorder content into an inaccessible sequence.
  • Writing a complex shorthand that teammates cannot safely maintain.

Developer notes

Move stable values into custom properties when a component needs themes or variants. Container queries may be a better choice than viewport queries when the same component appears in a full page and a narrow sidebar. Keep the simplest rule that expresses the actual relationship.

CSS Grid generator FAQ

Can I use minmax and repeat?

Yes. The track inputs accept normal CSS syntax supported by the browser rendering the preview.

Why does an invalid track value keep the previous layout?

The browser ignores invalid CSS declarations. Correct the track syntax and the preview will update.

Does the download include a framework?

No. It provides a minimal HTML starter and the generated CSS so it can be adapted to any stack.
